# 🌳 Голосовий квест-агент парку «Оствиця»

Голосові квести для парку історичної реконструкції
[**«Оствиця»**](https://ostvytsya.com.ua/) (Рівне). Термінал «спить» і **не реагує
ні на що**, доки дитина не промовить кодове слово персонажа (у Домовичка —
чемне **«Шановний»** / «Шановна» / «Шановні», у Дерева — «Мудрість», у
Повітрулі — «Князь»). Тоді персонаж оживає, голосом веде квест і відправляє
гравців далі.

Персонажі, голоси, кодові слова та самі запитання — **у конфігурації**, тож одним
кодом можна підняти скільки завгодно різних героїв (приклади — Водяник, Повітруля).

Проєкт складається з **двох частин**:

| Частина | Де живе | Модель | Для чого |
|---|---|---|---|
| 📱 **Мобільний застосунок** | Android-телефон у парку, [`mobile/`](mobile/) | **Google Gemini Live** (Native Audio) | власне квест: сон до кодового слова (офлайн-Vosk), розмова, аудіозапис і текстовий журнал кожної сесії |
| 🌐 **Веб-панель** | сервер, [`web/`](web/) | **OpenAI Realtime** або **Gemini Live** | редагувати персонажів, ганяти квест у браузері, бачити всі термінали |

Персонажі — ті самі файли `characters/*.yaml`. Створив у вебі → доступний і в
застосунку.

> 📜 Людиночитний сценарій: [`scripts/quest-domovychok.md`](scripts/quest-domovychok.md)

## Як це працює

**Мобільний застосунок** (термінал у парку):

```
        режим СПОКОЮ                              режим КВЕСТУ
 ┌────────────────────────┐  кодове слово ┌──────────────────────────────┐
 │ детектор кодового слова │ ───────────▶ │  Gemini Live  (Native Audio) │
 │ (Vosk, офлайн, тиша,    │              │  • персона + сценарій        │
 │  нічого не коштує)      │ ◀─── reset ──│  • запитання, підказки       │
 └────────────────────────┘  перемога/    │  • судить відповіді          │
        ▲        │            тайм-аут     │  • каже слово → кінець      │
   мікрофон   колонка                      └──────────────────────────────┘
```

Ключ Gemini лежить лише на самому телефоні — застосунок ходить до моделі
напряму, без нашого сервера.

**Веб-панель** (браузер):

```
                          ┌──────────────┐   ephemeral-токен   ┌──────────────┐
 ┌─────────┐ логін/пароль │  наш сервер  │────────────────────▶│    OpenAI    │
 │ браузер │─────────────▶│  (FastAPI)   │  промпт + голос     │  Realtime    │
 │         │              │              │◀══ WebRTC напряму ═▶│              │
 │  🎙 🔊  │              │              │                     └──────────────┘
 │         │◀═ WebSocket ═│    міст      │────────────────────▶┌──────────────┐
 └─────────┘   PCM-аудіо  └──────────────┘   аудіо + промпт    │ Gemini Live  │
                                 │                             └──────────────┘
                          characters/*.yaml
                                 ▲
                    статус раз на 5 хв │ 📱 термінали в парку
```

Ключі **ніколи не потрапляють у браузер**. Для OpenAI сервер видає
короткоживучий ephemeral-токен (звук іде напряму, з мінімальною затримкою);
для Gemini тримає міст і пересилає аудіо сам. В обох випадках промпт і голос
задає сервер — клієнт їх підмінити не може.

Логіку розмови веде модель — це робить діалог природним і дозволяє щедро
зараховувати відповіді (синоніми, відмінки), а не звіряти рядки в коді.

## 🌐 Веб-режим (OpenAI Realtime · Google Gemini Live)

Редактор персонажів, голосовий квест просто в браузері та панель усіх
терміналів. Персонажі — ті самі `characters/*.yaml`, що й у застосунку.

### Запуск

```bash
# 1. Залежності
pip install -r requirements-web.txt

# 2. Налаштування — СТВОРИ ФАЙЛ .env (саме .env, а не .env.example!)
cp .env.example .env                # Windows PowerShell: copy .env.example .env
#   OPENAI_API_KEY=...              ← ключ з https://platform.openai.com/api-keys
#   OSTVYTSYA_WEB_USER=admin
#   OSTVYTSYA_WEB_PASSWORD=...      ← початковий пароль адміністратора (лише для першого старту)
#   OSTVYTSYA_WEB_SECRET=...        ← необов'язково: без нього ключ згенерується і збережеться в базі

# 3. Старт
python -m web                       # → http://127.0.0.1:8080
```

Файл `.env` читається **автоматично** (і на Windows теж) — вручну експортувати
змінні не треба. При старті видно, що саме підхопилося:

```
📄 Прочитано налаштування з C:\...\ostvytsya\.env
🔑 OPENAI_API_KEY: sk-pro…(164 симв.)
🌐 Веб-квест на http://127.0.0.1:8080
```

Якщо бачиш `⚠️ Файл .env не знайдено` або `⚠️ Не задано OPENAI_API_KEY` —
перевір, що файл названо саме `.env` (Провідник Windows любить дописати `.txt`)
і лежить у корені проєкту.

Відкрий у браузері, увійди — і далі:

| Що | Де |
|---|---|
| Список персонажів | головна `/` |
| Створити персонажа | `+ Новий персонаж` |
| Змінити назву, промпт, голос, швидкість | `Редагувати` |
| Скопіювати персонажа з усім сценарієм | `Клонувати` → одразу відкриється копія |
| Видалити | `Видалити` (з підтвердженням) |
| **Голосовий квест** | `▶ Запустити квест` → дозволь мікрофон |

Квест **починається сам**, щойно дано доступ до мікрофона — так, ніби діти
щойно промовили кодове слово. Персонаж заговорить першим.

**Перебити персонажа не можна:** поки він говорить, мікрофон вимкнено
(`🔇 Персонаж говорить — слухай`), а коли договорить — вмикається знову
(`🎙 Твоя черга — говори`). Це і правило гри, і захист від того, щоб модель
чула саму себе з колонок.

### 📡 Термінали

Сторінка **`/agents`** показує всі мобільні термінали, що звітують у цю панель:
ідентифікатор, чи йде зараз квест, модель телефону, заряд (свій і
Bluetooth-пристроїв), координати та коли був останній звіт. Термінал, від якого
нічого не чути понад 12 хвилин, показано приглушено.

Там же — **перемоги команд**: коли квест пройдено до кінця (персонаж назвав
таємне слово), застосунок шле подію на `POST /api/agents/win`; панель показує
для кожного термінала кількість перемог (усього / сьогодні) та час останньої,
а внизу — список останніх перемог по парку (коли, термінал, персонаж,
тривалість квесту). Подія на телефоні спершу лягає в чергу на диску й
повторюється, доки сервер не підтвердить (немає мережі в мить перемоги — не
біда), а сервер розрізняє повтори за ідентифікатором сесії, тож дублів
немає. Для цього потрібна лише адреса сервера в налаштуваннях застосунку.

### 🔄 Синхронізація персонажів між терміналами

Телефони синхронізують персонажів через панель (адреса сервера в
налаштуваннях; типово — `https://ostvytsya.onrender.com`, тож працює одразу
після встановлення) за правилом «останній запис перемагає»:
кожна правка персонажа (голос, промпт, кодові слова, швидкість мови…)
оновлює його таймстамп `updated_at`, одразу асинхронно летить на сервер
(`POST /api/characters-sync`) і за ≤5 хвилин з'являється на всіх інших
терміналах. Типові персонажі з комплекту мають `updated_at = 0`, тож
будь-яка правка на будь-якому телефоні їх переважує.

Протокол навмисно без станів: телефон щотакту шле повний набір своїх
персонажів, сервер лишає собі новіші й відповідає тими, що новіші за
телефонні. Тому система самовідновлюється після будь-чого — рестарту чи
ефемерного диска сервера (перший же такт будь-якого телефона наповнює
сховище знову), втрачених запитів, довгого офлайну. Збій синхронізації
ніколи не чіпає квест: помилки тихо ігноруються до наступного такту.

Нові персонажі, створені на будь-якому телефоні, так само з'являються на
всіх інших (і на свіжовстановлених теж). Видалення синхронізується через
«надгробки» (`{id, deleted: true, updated_at}`) у тому самому LWW-потоці:
видалив на одному терміналі — зникне на всіх. Виняток — три незнищенні
персонажі парку (**Домовичок, Повітруля, Дерево**): їх можна лише
редагувати; пункт «Видалити» для них прихований, а сервер і застосунок
відкидають їхні надгробки навіть від телефонів зі старим APK.

Термінал з'являється у списку сам: звіти **увімкнені за замовчуванням**, а
адреса сервера типово — панель парку `https://ostvytsya.onrender.com`
(`kDefaultServerUrl` у `mobile/lib/constants.dart`). Інший сервер —
**Налаштування → Звіти в панель → Адреса сервера** у вигляді
`https://host:port`; порожнє поле означає типову адресу. Перемикач
«Надсилати статус у панель» вимикає лише звіти; синхронізація персонажів і
перемоги йдуть на вказану адресу завжди.

Звіт іде раз на 5 хвилин, у фоні, і ні на що не впливає — якщо сервер
недоступний, квест працює як завжди.

Про що варто знати заздалегідь:

* **номер телефону** Android віддає лише тоді, коли його записав на SIM-карту
  оператор. Здебільшого цього немає, і колонка лишається порожньою;
* **заряд Bluetooth-пристрою** публічного API не має — читаємо прихований, який
  доступний не на всіх прошивках;
* **координати** беруться з останньої відомої точки (щоб звіт був миттєвим і
  не садив батарею) і потребують дозволу на геолокацію.

Реєстр терміналів зберігається в базі панелі (SQLite, див. нижче) і
переживає перезапуски сервера; кожен термінал оновлює свій рядок раз на
5 хвилин. Кнопка 🗑 у рядку прибирає термінал зі списку
(`POST /api/agents/{id}/delete`) — для старих ідентифікаторів і списаних
телефонів; увімкнений телефон з'явиться знову зі своїм наступним звітом,
а його історія перемог лишається.

### 🚀 Деплой на Render (з постійним диском на 1 ГБ)

У репозиторії є [`render.yaml`](render.yaml) — Blueprint, який створює сервіс,
постійний диск і змінні оточення. Диск потрібен обов'язково: власна тека
сервісу на Render **ефемерна** — усе записане туди зникає при кожному деплої
та перезапуску, а база панелі — це один файл SQLite. Диски Render дає лише на
платних планах (Starter, ~$7/міс) плюс ~$0.25 за ГБ диска на місяць.

**Крок 1. Створити сервіс із Blueprint.** Render → **New → Blueprint** →
під'єднати GitHub і обрати репозиторій `ostvytsya`, гілку з якої деплоїш →
Render покаже, що створить із `render.yaml`: веб-сервіс `ostvytsya-web` (план
Starter, регіон Frankfurt), диск `ostvytsya-data` на 1 ГБ у `/var/data`,
змінні → **Apply**. У формі Blueprint він попросить значення для секретів із
`sync: false` — можна заповнити одразу або пізніше в Environment.

**Крок 2. Задати секрети** (сервіс → **Environment**):

| Змінна | Що вписати |
|---|---|
| `OSTVYTSYA_WEB_PASSWORD` | пароль адміністратора для **першого** входу (логін — `admin`, змінна `OSTVYTSYA_WEB_USER`). Читається лише один раз, коли база ще порожня; далі пароль живе в базі. Можна не задавати — тоді панель згенерує випадковий і надрукує в **Logs** при першому старті |
| `OPENAI_API_KEY` | ключ OpenAI — для квесту в браузері з OpenAI-персонажами |
| `GEMINI_API_KEY` | ключ Gemini — лише якщо в браузері ганяєш персонажів з моделлю Google |
| `OSTVYTSYA_WEB_SECRET` | нічого: Render згенерував сам (`generateValue`) — це ключ підпису сесій, без нього кожен деплой викидав би на логін |
| `OSTVYTSYA_DB_PATH` | уже `/var/data/ostvytsya.db` із Blueprint — шлях бази **на диску** |

Телефонам у парку ключі на сервері не потрібні: вони ходять до Gemini напряму,
а на сервер лише шлють статуси й персонажів.

**Крок 3. Перший старт — база створюється сама.** Диск монтується порожнім;
при першому запиті панель створює `/var/data/ostvytsya.db`, усі таблиці
(`CREATE TABLE IF NOT EXISTS`), імпортує персонажів із `characters/*.yaml` у
таблицю `characters` і створює адміністратора з `OSTVYTSYA_WEB_USER` /
`OSTVYTSYA_WEB_PASSWORD`. У **Logs** має бути:

```
🗄️  База панелі (SQLite): /var/data/ostvytsya.db
👤 Адміністратор: «admin» (пароль — у базі; забув → python -m web --set-admin-password …)
🗄️  Персонажі редактора: та сама база SQLite (storage.backend: sqlite)
```

Якщо пароль не задавали — замість другого рядка буде `🔑 Створено
адміністратора «admin» із ВИПАДКОВИМ паролем: …` (він же лежить у
`/var/data/initial-admin-password.txt` на диску, поки пароль не змінять).

**Крок 4. Увійти й змінити пароль.** Відкрий `https://<сервіс>.onrender.com`,
увійди `admin` + пароль із кроку 2, зайди в **/account** і постав постійний
пароль. Після цього змінна `OSTVYTSYA_WEB_PASSWORD` більше ні на що не
впливає — її можна видалити з Environment. Забув пароль — Render → сервіс →
**Shell**:

```bash
python -m web --set-admin-password "новий-пароль"
```

**Крок 5. Телефони.** Якщо сервіс названо `ostvytsya` (адреса
`https://ostvytsya.onrender.com`) — нічого робити не треба: ця адреса зашита
в застосунок як типова, звіти ввімкнені, і термінали з'являться на `/agents`
самі за кілька хвилин, а персонажі почнуть синхронізуватися. Інша адреса —
у застосунку Налаштування → Звіти в панель → «Адреса сервера»
(`https://<сервіс>.onrender.com`, з протоколом, без шляху).

**Як переконатися, що база справді на диску.** Зроби деплой (Manual Deploy →
Deploy latest commit): після нього термінали, правки персонажів і перемоги на
місці, а в Logs знову `/var/data/ostvytsya.db`. Резервна копія — Shell:
`sqlite3 /var/data/ostvytsya.db ".backup /var/data/backup.db"` і завантажити
файл, або просто копія диска через Render → Disks → Snapshots.

Що змінилося порівняно зі звичайним сервером: порт і адресу підбирати не треба
(Render задає `PORT`, додаток слухає `0.0.0.0`), сесійна кука позначається
`Secure`, uvicorn працює з `proxy_headers` — інакше за зворотним проксі
ламаються редиректи й WebSocket (`wss`) для Gemini-персонажів. Сервіс із
диском працює в одному екземплярі, деплой — із короткою паузою замість
zero-downtime; для панелі парку це нормально.

> Без диска (free-план) панель теж запуститься, але після кожного деплою
> база буде порожня: адміністратор створиться заново з
> `OSTVYTSYA_WEB_PASSWORD`, термінали відзвітують за 5 хвилин, а от правки
> персонажів із телефонів і перемоги зникнуть. Для персонажів редактора є
> обхід через Render PostgreSQL (див. закоментований блок у `render.yaml`),
> але простіше й дешевше — диск.

### 🗄️ База панелі (SQLite) — усе зберігається постійно

Панель **нічого не тримає лише в пам'яті**: усі її дані живуть в одному файлі
SQLite `data/ostvytsya.db` (шлях — `OSTVYTSYA_DB_PATH`; жодних зовнішніх
залежностей, `sqlite3` є в самому Python). Після перезапуску сервера все на
місці одразу.

| Таблиця | Що там |
|---|---|
| `agents` | останній статус кожного термінала (`/agents`) |
| `mobile_characters` | персонажі, синхронізовані з телефонів (і «надгробки» видалених) |
| `characters` | персонажі веб-редактора (див. `storage.backend` нижче) |
| `users` | адміністратор панелі (хеш пароля pbkdf2) |
| `settings` | ключ підпису сесій, якщо не задано `OSTVYTSYA_WEB_SECRET` |

Міграцій, ORM чи ручного керування схемою немає — таблиці створюються самі
при першому зверненні (`CREATE TABLE IF NOT EXISTS`). Резервна копія — це
просто копія файлу (`sqlite3 data/ostvytsya.db ".backup backup.db"`).

**Де зберігати персонажів редактора** — `config.yaml → storage.backend` (або
змінна `OSTVYTSYA_STORAGE_BACKEND`):

| `storage.backend` | Де живуть персонажі редактора | Коли обирати |
|---|---|---|
| `sqlite` (типово) | таблиця `characters` у тій самій базі | звичайний сервер/VPS |
| `files` | `characters/*.yaml` у репозиторії | авторство сценаріїв прямо в git |
| `postgresql` | Render Managed PostgreSQL (`DATABASE_URL`) | хостинг без постійного диска |

При першому зверненні до порожньої бази (SQLite чи PostgreSQL) персонажі з
`characters/*.yaml` імпортуються туди автоматично (одноразово) — щоб
Домовичок, Водяник, Повітруля, Дерево, Вітроплав і Лорд над Монетою не
«зникли» після переходу на базу.
Старий прапорець `storage.render: yes` і далі означає `postgresql`.

> ⚠️ **Render та інші хостинги з ефемерним диском:** файл SQLite зникне при
> передеплої. `render.yaml` тому монтує Persistent Disk у `/var/data` і задає
> `OSTVYTSYA_DB_PATH=/var/data/ostvytsya.db` — див. «Деплой на Render» вище.
> Альтернатива лише для персонажів редактора — `postgresql`; статуси
> терміналів, перемоги й адміністратор без диска все одно зникатимуть.

### 👤 Адміністратор

У панелі **один** обліковий запис адміністратора, і живе він у базі, а не в
`.env`. Змінні `OSTVYTSYA_WEB_USER` / `OSTVYTSYA_WEB_PASSWORD` (або
`…_PASSWORD_HASH`) читаються лише при **першому** старті — щоб його створити.
Якщо пароль не задано, панель згенерує випадковий, надрукує в лог і покладе в
`initial-admin-password.txt` поруч із базою (типово `data/`, на Render —
`/var/data/`); файл зникає після першої зміни пароля.

Далі пароль змінюється лише в самій панелі — клік на своє ім'я вгорі
(`/account`) — або з сервера, якщо забув:

```bash
python -m web --set-admin-password "новий-пароль"
```

Змінні середовища на вже створеного адміністратора **не впливають**: старий
пароль у `.env` не «відкотить» новий після перезапуску.

### Мова та подача

До промпту **кожного** персонажа автоматично додаються два блоки
(див. `domovyk_quest/prompt.py`) — однаково для OpenAI й Gemini:

* **🇺🇦 мова** — говорити виключно українською, з питомою вимовою, без
  іноземного акценту. Голосові моделі OpenAI без цього читають українську
  з англійським акцентом;
* **🎭 подача** — грати голосом як актор: емоції, паузи, сміх, шепіт, казкова
  барвиста мова, а не рівний «дикторський» тон.

Писати це в кожному персонажі не треба — воно діє завжди й в обох режимах.

### Персонажі: сценарій чи вільний промпт

> ⚠️ **Розділ «Персонажі» в панелі тимчасово приховано** (список, редактор,
> квест у браузері): веб-редактор і телефони — окремі сховища, і правки в
> ньому на термінали не потрапляють, лише збивають з пантелику. Головна
> сторінка панелі зараз — «Термінали». Код, API (`/api/characters…`) і
> шаблони на місці; повернути розділ — змінна `OSTVYTSYA_CHARACTERS_UI=1`
> (у Render → Environment) і перезапуск.

* **Наявні YAML-сценарії** (Домовичок, Повітруля…) працюють у вебі як є —
  інструкція збирається з `persona`/`style`/`questions`/`directives`.
  У редакторі можна подивитися, який саме промпт іде в модель.
* **Нові персонажі** зручно описати вільним текстом у полі «Промпт персонажа».
  Якщо це поле заповнене — воно **повністю замінює** зібраний сценарій.

Редагування у вебі **зберігає коментарі й форматування** YAML: правляться лише
ті поля, які ти справді змінив, решта файлу лишається недоторканою.

**Скинути до типового.** У редакторі персонажа з комплекту (є файл
`characters/<id>.yaml` у репозиторії) внизу є кнопка «↺ Скинути до типового»
(`POST /api/characters/{id}/reset`): персонаж у базі панелі повертається до
версії з репозиторію — сценарій, промпт, голос, кодові слова. Для персонажів,
створених у редакторі, кнопки немає; у файловому бекенді теж (YAML і є
сховищем). Та сама кнопка є в редакторі персонажа на телефоні: там вона
повертає версію з APK і синхронізує її на інші термінали як звичайну правку
(з новим `updated_at`), тож скидання перемагає попередні правки скрізь.

### Безпека

* доступ лише за логіном і паролем; пароль зберігається як `pbkdf2_sha256`-хеш
  (можна одразу покласти хеш: `python -m web --hash-password "пароль"`);
* ключ OpenAI не потрапляє в браузер — лише короткоживучий ephemeral-токен;
* промпт і голос задає сервер, клієнт їх не підмінить;
* форми й API захищені CSRF-токеном, кука — `SameSite=lax`.

> ⚠️ Мікрофон у браузері доступний лише на `https://` або `localhost`. Якщо
> відкриваєш з іншої машини — постав HTTPS (напр. nginx + Let's Encrypt) і
> увімкни `https_only=True` для куки у `web/app.py`.

## Додати нового персонажа

1. `cp characters/domovychok.yaml characters/berehynia.yaml` — і зміни `id`,
   `display_name`, `voice`, `wake_words`, `win_word`, `persona`, `questions`.
   Персонаж без загадок (екскурсовод, зазивайло) — краще з вільним
   `system_prompt` (див. `vitroplav.yaml`, `lord-monety.yaml`).
2. Поля **поведінки сесії** в мобільному застосунку (усі необов'язкові):

   | Поле | Що робить | Приклад |
   |---|---|---|
   | `wake_words` | кодові слова пробудження (офлайн-Vosk) | `["Одісея"]` |
   | `win_word` | слово, яким персонаж завершує квест (перемога). Порожнє — квест не завершується словом персонажа | `"Ідола"` / `""` |
   | `stop_words` | слова від ГОСТЕЙ, що завершують сесію: персонаж прощається, сесія закривається | `["Каліпсо"]` |
   | `wake_on_voice` | прокидатись від будь-якого голосу, без кодового слова (зазивайло) | `true` |
   | `inactivity_timeout_s` | скільки секунд тиші завершують сесію (типово 1800) | `60` |
   | `answer_wait_s` | **час очікування відповіді**: скільки секунд персонаж мовчки слухає людей після своєї репліки. Якщо ніхто не заговорив — застосунок просить його продовжити самому (повторити питання, підказати, вести розповідь далі), бо модель сама по себе говорить лише у відповідь. Відлік — від кінця відтворення репліки. Типово `10`; `0` — без обмеження (зазивайло). У застосунку — поле «Час очікування відповіді» в редакторі персонажа | `10` / `0` |
   | `context_compression` | **стискати контекст розмови**: Gemini обрізає історію до останніх ~8–15 хвилин (пороги 24 000 → 12 000 токенів у `constants.dart`), і довга сесія коштує у 2–3 рази дешевше. `false` — типове вікно Google: персонаж пам'ятає весь квест, але кожен хід перечитує всю історію. Типово `true`; у Повітрулі `false` (лік знайдених слів). Перемикач у редакторі персонажа на телефоні, діє з наступного запуску квесту | `true` / `false` |

3. Перегенеруй мобільні копії й додай id у `CharacterStore._defaultIds`
   (`mobile/lib/services/character_store.dart`), щоб персонаж з'явився на
   телефонах при першому запуску:

   ```bash
   python scripts/build_mobile_characters.py        # characters/*.yaml → mobile/assets/characters/*.json
   ```

   Той самий скрипт треба запускати після КОЖНОЇ правки `characters/*.yaml`
   чи `domovyk_quest/prompt.py` — мобільний застосунок YAML не читає.
4. Веб-панель підхопить нового персонажа сама: порожня база імпортує
   `characters/*.yaml`, а вже наповнену можна доповнити через редактор.

### Що насправді формує рахунок

1. **Аудіо, яке модель вимовила** (вихід) — найдорожчі токени, але їх мало:
   50 хвилин мовлення персонажа ≈ 75–96 тис. токенів ≈ **$0.90–1.15**.
2. **Аудіо, яке модель почула** (вхід). Мікрофон **апаратно вимкнений**, поки
   персонаж говорить (`AudioPipeline`), тож у хмару йде лише той час, коли
   персонаж мовчить: у сцені «50 хв говорить персонаж / 10 хв люди» це ≈ 10 хв
   ≈ 19 тис. токенів ≈ **$0.06**. Тиша в цих 10 хвилинах коштує так само, як
   мова, але це копійки.
3. **Перечитування історії — головна стаття.** Live API на **кожному ході**
   подає моделі весь контекст: системну інструкцію (3–7 тис. текстових
   токенів, у Повітрулі найбільше) **і всю попередню розмову як аудіо**, і
   тарифікує це як вхід ($3.00 за 1 млн аудіо-токенів). Тому вартість сесії
   росте **квадратично** від її тривалості: 15-й хід перечитує 14 попередніх,
   75-й — 74. Для години з ~75 ходами це ≈ 3.5 млн аудіо-токенів ≈ **$10.7**
   плюс ≈ $0.3 за системну інструкцію ×75. Обмежує це лише **стискання
   контексту** (`contextWindowCompression`): у застосунку це налаштування
   персонажа (`context_compression`, перемикач «Стискати контекст розмови»).
   Увімкнено — історія обрізається до останніх ~8–15 хвилин (пороги
   24 000 → 12 000 токенів), і квадрат не росте. Вимкнено (Повітруля) — типові
   пороги Google біля 80 % вікна моделі, що для годинної сесії практично не
   спрацьовує, зате персонаж пам'ятає все.

### Як перевірити на реальних квестах

У кожному журналі сесії (`Documents/Оствиця/logs/quest_<час>.txt`, екран

```
[17:38:12] система: Токени ходу 12: контекст 21 480 (аудіо 15 900, текст 5 580), відповідь 1 020. За сесію: вхід 148 300, вихід 12 400 ≈ $0.594
```

Це лічильники `usageMetadata`, які надсилає сам Gemini, помножені на ціни з
`constants.dart` (`kGeminiAudioInputUsdPer1M` тощо — онови, якщо Google
змінить прайс). Порівняй підсумок останнього ходу з рахунком у Google AI
Studio → Billing: якщо збігається — оцінки вище можна масштабувати на свій
розклад роботи парку.

### Опції «вартість ↔ якість» (від найдієвішої)

| Опція | Економія | Ціна в якості | Як |
|---|---|---|---|
| **Стискання контексту** (пороги 24 000 → 12 000 токенів) — **уже ввімкнено** для всіх персонажів, крім Повітрулі | суцільна година $12–15 → ≈ $6; квести до 15 хв — без змін | модель пам'ятає лише останні ~8–15 хв розмови: для квестів норма, для довгої екскурсії — навіть добре; вимкнено там, де треба пам'ятати все (Повітруля) | перемикач «Стискати контекст розмови» в редакторі персонажа / `context_compression` у YAML; пороги — `kGeminiContextTriggerTokens` у `constants.dart` |
| **Коротші сесії** | квадратична стаття падає вчетверо при вдвічі коротшій сесії | немає, якщо сесія природно завершується (перемога, стоп-слово) | для Вітроплава кажіть «Каліпсо» після кожного рейсу; тайм-аути тиші вже виставлені (`inactivity_timeout_s`) |
| **Менше ходів** | кожен хід = ще одне перечитування історії + відповідь | довше очікування відповіді | `answer_wait_s` можна збільшити там, де люди довго мовчать із поважної причини (фізичний пошук); у Лорда — 0 |
| **Коротша системна інструкція** | ≈ $0.3 на годину при 75 ходах (Повітруля ~16 тис. символів) | треба ущільнити правила, не втративши сценарій | скорочувати `directives`/`style`, не дублювати одне правило тричі |
| **Дешевша модель Gemini** — Gemini 2.0 Flash Live (аудіо $2.10 / $8.50), якщо ще доступна | ≈ −30 % на всіх статтях | помітно гірша українська, старіша поведінка, може бути знята з підтримки | `kGeminiLiveModel` / `GEMINI_LIVE_MODEL` |
| **OpenAI `gpt-realtime-2.1-mini`** | суцільна година ≈ $2 замість $12–15 | акцент в українській вимові, інший набір голосів; довжина сесії обмежена платформою | у мобільному редакторі персонажа — провайдер «OpenAI» (`kOpenAiRealtimeModel`) |
| **Стрімити менше тиші** | вже зроблено: мікрофон вимкнений під час мовлення персонажа | — | далі економити немає на чому: решта тиші ≈ $0.006 за хвилину |

Що **не** варто робити задля економії: скорочувати репліки персонажів чи
прибирати повтор таємного слова — вихідне аудіо це лише ~$1 на годину, а
квест від цього гірший.

### Приватність

- До кодового слова **нічого** не йде в хмару — телефон слухає локально (Vosk).
- Під час квесту в Google йде лише голос біля терміналу в проміжках, коли
  персонаж мовчить; аудіозапис і журнал сесії лишаються на самому телефоні.

## Розв'язання проблем

| Симптом | Що робити |
|---|---|
| **Веб:** не можу увійти після першого запуску | пароль адміністратора — той, що був у `OSTVYTSYA_WEB_PASSWORD` при ПЕРШОМУ старті, або згенерований (див. лог чи `data/initial-admin-password.txt`). Забув — `python -m web --set-admin-password "новий"` |
| **Веб:** «Не задано OPENAI_API_KEY», хоча ключ у файлі є | ключ вписано у `.env.example` замість `.env`, або файл названо `.env.txt`. Перевір рядок `📄 Прочитано налаштування з …` при старті — якщо його немає, файл не знайдено |
| **Веб:** «не вдалося отримати токен» / 502 | перевір `OPENAI_API_KEY` та баланс акаунта OpenAI; текст помилки від OpenAI видно в логу сервера |
| **Веб:** браузер не питає мікрофон | мікрофон дозволений лише на `https://` або `localhost` — постав HTTPS чи відкривай локально |
| **Веб:** «Недійсний CSRF-токен» | сторінка провисіла з попереднього запуску сервера — просто онови її (F5) |
| **Веб:** персонажі/термінали зникають після передеплою на Render | диск хостингу ефемерний, а база панелі — файл SQLite. Прив'яжи Persistent Disk і задай `OSTVYTSYA_DB_PATH` на нього, або для персонажів редактора увімкни `storage.backend: postgresql` — див. розділ «База панелі» |
| **Веб:** `storage.backend: postgresql потребує пакет psycopg` | забув `pip install -r requirements-web.txt` після оновлення (там уже є `psycopg[binary]`) |
| **Веб:** `не задано DATABASE_URL` при `storage.backend: postgresql` | прив'яжи Managed PostgreSQL до сервісу в Render (підставить сам) або впиши рядок з'єднання в `.env` для локального тесту |
| **Веб:** забув пароль адміністратора | на сервері: `python -m web --set-admin-password "новий"`. Початковий згенерований пароль — у `data/initial-admin-password.txt`, якщо його ще не змінювали |
| **Веб:** «Адміністратора ще не створено — база панелі недоступна» | панель не змогла відкрити/створити `data/ostvytsya.db`: перевір права на теку або вкажи інший шлях через `OSTVYTSYA_DB_PATH` |
| **Термінали:** застосунок не з'являється на `/agents` | у застосунку перевір, що «Надсилати статус у панель» увімкнено (типово так) і адреса сервера — саме ця панель (типово `https://ostvytsya.onrender.com`, формат `https://host:port`). Перший звіт іде одразу після збереження налаштувань |
| **Термінали:** порожні координати | застосунок питає дозвіл на геолокацію на головному екрані (і в налаштуваннях, і при старті квесту) — його відхилили: Android → Налаштування → Застосунки → Оствиця → Дозволи → Місцезнаходження. Також має бути ввімкнена геолокація на телефоні. Якщо «останньої відомої» точки в системі немає, застосунок замовляє нове визначення (до 15 с) перед звітом, тож координати з'являться з наступним звітом (≤5 хв). Клік по координатах у панелі відкриває Google Maps |
| **Термінали:** порожній номер телефону | номер Android віддає, лише якщо його записав на SIM оператор — здебільшого його там немає |
| **Термінали:** правка персонажа не з'явилась на інших телефонах | на ОБОХ телефонах має бути вказана адреса сервера; зачекай до 5 хвилин (такт синхронізації) і перевір, що телефони мають інтернет |
| **Мобільний:** треба розібрати, що сталося під час квесту | кожна спроба пише текстовий журнал із таймкодами (`[17:38:12] персонаж: …`) у `Documents/Оствиця/logs/quest_<час>.txt` — та сама назва, що й в аудіозапису `Music/Оствиця/quest_<час>.m4a`. У застосунку: головний екран → «Журнали сесій» → кнопка «Копіювати» біля журналу (або відкрий і скопіюй) — і встав у чат для розбору. Журнал пишеться завжди, навіть якщо запис аудіо вимкнено |
| **Мобільний:** «Застосунок нещодавно аварійно завершився… LOW_MEMORY (код 3)» | процес убила система через нестачу пам'яті. У версіях до вересня 2026 причиною був витік у плагіні Vosk (кожне відкриття екрана квесту вантажило ще одну копію моделі на сотні МБ) — виправлено: модель одна на весь процес. Якщо повторюється — відкрий журнали двох-трьох попередніх сесій і порівняй рядки «Пам'ять…» на старті й наприкінці: росте «процес» від сесії до сесії — витік у застосунку (надішли журнали), мало «вільно на пристрої» ще до старту — тісно самому телефону (закрий інші застосунки, перезавантаж) |
| **Мобільний:** у діагностиці «З'єднання з Gemini відновлено (goAway…)» | це норма: одне WebSocket-з'єднання Live API живе ~10 хвилин, застосунок сам перепід'єднується з handle відновлення сесії, і розмова триває. Те саме при короткому зникненні мережі (wifi ↔ 4g). Квест завершується лише якщо 5 спроб поспіль не вдалися |
| **Веб:** після перезапуску сервера викидає на логін | не заданий `OSTVYTSYA_WEB_SECRET` — без нього ключ підпису куки щоразу новий |
